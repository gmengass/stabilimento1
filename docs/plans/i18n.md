# Plan: Interface languages (IT/EN), switchable anytime

Roadmap: Milestone 0. Branch: `feat/i18n`. Decision: ADR 0005 (library, no URL locale, switcher rules).

## Goal
Every screen renders in `it` (default) or `en` via next-intl, and a switcher on every screen changes
the language at once without losing form input; the preference lives in a cookie until Auth adds `user.locale`.

## Approach
- next-intl in "without i18n routing" mode (ADR 0005: no `[locale]` segment, no `proxy.ts`).
  `createNextIntlPlugin` in `next.config.ts`; `src/i18n/request.ts` (`getRequestConfig`) supplies
  locale, messages, `timeZone: "Europe/Rome"`, and a `eur` currency format.
- Messages: `messages/it.json`, `messages/en.json` (repo root, per ADR), namespaced by screen
  (`common`, `home`, later `login`). Keys typed via next-intl `AppConfig` augmentation from `it.json`.
- Locale order: pure `resolveLocale({ user, cookie })` returns the first valid of user preference,
  `locale` cookie, `"it"`. Callers pass no `user` today; Auth supplies it. No Accept-Language (ADR order).
- Switcher: client component in the root layout header (so on every screen, incl. future login).
  It calls server action `setLocale(locale)`: Zod-validated, sets cookie `locale` (path `/`, SameSite=Lax,
  1 year, httpOnly), then the client calls `router.refresh()`. The server re-renders, client state stays
  (no navigation). Assumption to verify: a cookie set in a server action refreshes the current route in Next 16.
- `<html lang>` follows the locale; `generateMetadata` translates the title and description.
- Booking `date` strings get a helper that formats a `YYYY-MM-DD` date as a calendar day (no timezone
  shift, ADR 0004); timestamps format in Europe/Rome.
- No hard-coded strings: `react/jsx-no-literals` on `src/app/**`, `src/components/**`.

## Acceptance criteria
1. No cookie: `/` renders Italian with `<html lang="it">`. Cookie `locale=en`: English, `lang="en"`.
2. Cookie `locale=fr` or garbage: Italian, no error. `setLocale("fr")` is rejected and sets no cookie.
3. Both message files have the same key set and the same ICU placeholders per key.
4. `resolveLocale`: user beats cookie beats default; invalid values are skipped at each level.
5. E2E: type into a test input, switch to English. Text changes without a full reload, the input keeps its
   value, the URL is unchanged, and the choice survives a reload.
6. `format.ts`: `2026-03-29` (DST day) formats as 29 March in both locales; EUR shows as `1.234,50 €` (it), `€1,234.50` (en).
7. `/health` is unaffected. `npm run lint` fails on a JSX string literal in `src/app`.

## Risks and edge cases
- `cacheComponents: true`: reading `cookies()` in the root layout fails the build. Resolved with
  `export const instant = false` on the root layout (blocking route, per Next 16 docs).
- Shared tablet: until Auth ships, the locale follows the device cookie (accepted, ADR 0005).
- Uncontrolled inputs survive `router.refresh()` only if not remounted. AC 5 covers this.
- Server/client date formatting mismatch: fixed `timeZone` in request config and provider.

## Deferred (Auth item)
- `user.locale` column (`text not null default 'it'`, check in ('it','en'), down drops it).
- `setLocale` also updates the user row when logged in; `request.ts` passes the session user's locale.
- On login, overwrite the cookie with the user's saved preference.
- Switcher on login page: comes from the root layout; placement check only.

## Decided
- Playwright added now (owner, 2026-11-11). Runs in CI; locally use the system Chrome.
- Cookie `Secure` in production: ADR 0003 serves the LAN over HTTPS via Caddy.
- No Accept-Language detection (ADR 0005).
