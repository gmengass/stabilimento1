# Plan: Interface languages IT/EN (ADR 0005)

**Goal**: Every screen renders in Italian (default) or English, switchable anytime without reload or lost input, with a ready seam for the logged-in user's saved preference.

## Acceptance criteria
- [ ] Given no `locale` cookie, When any page loads, Then it renders Italian and `<html lang="it">`
- [ ] Given cookie `locale=en`, Then English; given an invalid cookie (`fr`, empty), Then Italian. No Accept-Language (ADR 0005 fixes the chain: user pref -> cookie -> `it`)
- [ ] Given `getUserLocalePreference()` returns `en` (mocked), Then it wins over cookie `it`. Today it returns `null`
- [ ] When the switcher is used, Then the cookie is set (path `/`, SameSite=Lax, 1 year), the page re-renders in place, and text typed into an input on the page survives
- [ ] `setLocale` rejects values outside `it|en` (Zod) and leaves the cookie unchanged
- [ ] `messages/it.json` and `messages/en.json` have identical key sets, no empty values and the same ICU placeholders per key (unit test fails otherwise)
- [ ] `formatBookingDate("2026-03-29", locale)` and `("2026-10-25", …)` show that same calendar day in both locales on a machine with any TZ (DST boundaries, ADR 0004)
- [ ] `formatTimestamp(utc, locale)` converts to `Europe/Rome` only at the edge; `formatEur(123450)` gives `1.234,50 €` (it) / `€1,234.50` (en), with NBSP normalized in tests
- [ ] `npm run lint` fails on a JSX string or a user-facing attribute literal in `src/app` or `src/components`; `npm run lint`, `typecheck` and `test` pass; `next build` succeeds with `cacheComponents`

## Data / API changes
- No migration. Auth item adds `user.locale` (`it|en`, nullable) and implements the two seams (ADR 0005 Consequences).
- New server action `setLocale(locale: Locale): Promise<void>`. No routes, no proxy/middleware, no locale in the URL.

## Risks and edge cases
- `cacheComponents: true` in `next.config.ts`: `cookies()` in the root layout may need a `<Suspense>` boundary or the build fails. Verify against `node_modules/next/dist/docs/` and next-intl's "without i18n routing" guide.
- Lost input: a full reload or a remount keyed on locale wipes form state. Use action + refresh in a transition only.
- Dates: never `new Date("YYYY-MM-DD")` in local TZ. Format booking days via `Date.UTC` + `timeZone: "UTC"`.
- Shared tablet: the cookie is per device; the user preference overrides it after login (seam test).
- Lint gaps: the rule misses non-JSX strings (metadata, errors, Zod messages). Review covers those.
- Stale cookie with a removed locale: falls back to `it`, never throws.
